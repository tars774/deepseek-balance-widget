# ADR-006：节假日规则 = 本地 DayOfWeek 优先（周末一律空闲）

- 状态：已接受（探针 C 实证）
- 日期：2026-09-28
- 关联：[deepseek-api.md](../deepseek-api.md) · [probe-results.md](../probe-results.md)

## 背景

峰谷判定依赖"今天是工作日、周末还是法定节假日"。数据源为两个第三方节假日 API（主源 xiaoai、备源 dreace）。用户原始需求明确：**"调休上班的周末全天空闲（周末一律空闲）"**。风险点：调休补班日（如国庆前后把周末调成交班日）在 API 里如何表达？API 不可达时如何兜底？

## 决策

**判定顺序（规则层）：**

1. 本地 `DayOfWeek`（按北京日期）为周六/周日 → **一律全天空闲，不看 API**；
2. 周一至周五且 API 报法定节假日 → 全天空闲；
3. 其余（周一至周五且 API 报工作日/数据不可用）→ 工作日时段（09:00–12:00、14:00–18:00 高峰，其余空闲）；
4. 工作日 + "补班/周末"等矛盾数据一律忽略。

**节假日数据链**：主源成功判定 = 业务层 `code∈{0,200}` + **日期回显校验**（无匹配日期判失败，禁止静默取 `data[0]`）；主备双源 + 按北京日期缓存 + 前瞻拉取 ≤400 天（本地周末短路不请求）+ 失败退避 1/5/15 分钟全局门；双源不可用 → Degraded（UI 底行"数据离线"小图标），峰谷按规则 1/3 本地逻辑照常。

## 理由

1. **两源对补班周末的字面语义都不可信**：探针 C 实测两个补班周末（2025-10-11 周六、2025-09-28 周日）——主源报 `daytype=3`+`holiday="国庆节调休"`，备源报 `isHoliday=false`+`type="工作日"`+`note="补班工作日"`。**两者字面都像"工作日"**，若按 API 字面判定，补班周末会被误判为高峰日，直接违背用户"周末一律空闲"的原始规则。唯有"本地星期优先"能稳定兜住（两日期双源验证全天空闲）。
2. **本地星期零成本、零失败面**：周六/周日的判定不依赖网络；API 只在"周一至五是否法定节假日"这一个维度上有增量价值——把外部依赖压缩到最小面。
3. **降级行为可预期**：Degraded（双源失败/退避窗口）下唯一损失是"法定节假日"识别（会把节假日工作日误判为高峰日），周末仍由规则 1 正确兜底；多源冗余 + 15 分钟封顶退避使误判窗口很短，且 UI 明示"数据离线"。

## 后果

- 正面：用户规则（周末一律空闲）获得确定性保证；API 故障的影响面最小化；缓存 + 前瞻使跨天/长假倒计时零重复请求（计数器实证每日期恰拉一次）。
- 负面：若未来官方政策改为"补班周末真的上班"，本规则会把该日误判为全天空闲——这是用户显式选择的产品语义（修改需更新 [ui-selection.md](../ui-selection.md) 类绑定文档与本文 ADR）。
- 中性：主源冷启动 8s 超时为已知瞬态（failover 兜底，真实触发过一次并正确切换）。

## 替代方案

| 方案 | 结论 |
| --- | --- |
| 完全信任 API（含补班日） | 否决（两源字面语义相反且都违背用户规则，实测证据见上） |
| 完全本地（不用 API，仅周一至五逻辑） | 否决（法定节假日全天空闲无法识别，节假日误判为高峰日体验差） |
| 规则可配置（用户自选周末是否空闲） | 未采用（当前用户规则明确；可配置性列入路线图评估） |
