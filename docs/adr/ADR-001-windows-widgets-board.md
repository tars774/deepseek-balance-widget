# ADR-001：放弃 Win11 官方小组件板，采用托盘 + 弹出面板

- 状态：已接受（用户拍板，需求基线既定决策）
- 日期：2026-09-28
- 关联：[README 已知限制](../../README.md#已知平台限制与解决方案) · [architecture.md](../architecture.md)

## 背景

需求是"Windows 桌面小组件"。Windows 11 提供官方小组件板（Widgets Board），从"平台原生"直觉看是候选载体。需要评估其接入成本与本项目约束（C# + WPF + .NET 8、单文件 exe 侧载交付、快速迭代）的匹配度。

## 决策

**放弃 Win11 官方小组件板，改用系统托盘常驻图标 + 左键弹出无边框面板**的形态。

## 理由

1. **接入门槛高**：官方小组件板需要 MSIX 打包与 WinRT/COM 互操作（实现 IWidgetProvider 等接口），与"单文件 exe 免安装侧载"的交付目标直接冲突（MSIX 是安装包形态）。
2. **开发体验差**：小组件板无 XAML 设计器支持，UI 迭代成本高；而 WPF 路线可以先用纯 HTML 做高保真预览（本项目实际走了 12 候选选型流程，见 [ADR-004](ADR-004-ui-preview-first.md)），再用 WPF 逐像素还原。
3. **交互模型不匹配**：小组件板的内容被动展示在系统聚合面板里，无法提供"托盘状态灯随峰谷变色""点击弹出、失焦隐藏""右缘停靠可拖动钉住"这类常驻轻量交互。
4. **技术栈完全兼容**：托盘 + WPF 面板路线与既有选型（H.NotifyIcon.Wpf + .NET 8）零冲突，探针 A 全部实证可行（8/8）。

## 后果

- 正面：免安装单文件交付成立；UI 可控可预览；交互自由（图标变色/tooltip/菜单/面板）。
- 负面：失去"Windows 11 原生小组件"的曝光面；托盘图标可能落在溢出折叠区，产生"左键≈总是显示"的行为边界（已在 README 说明并引导固定图标）。
- 中性：面板本身仍是普通 Win32 窗口（Topmost、`WS_EX_TOOLWINDOW`），不依赖任何 Win11-only API，Win10 同样可用。

## 替代方案

| 方案 | 结论 |
| --- | --- |
| Win11 官方小组件板 | 否决（MSIX + COM 互操作 + 无设计器，与免安装交付冲突） |
| 独立常驻悬浮窗（非托盘） | 未采用（常驻占屏；托盘 + 按需弹出更轻） |
| Electron/WebView2 混合 | 未采用（体积与内存代价大，见 [ADR-005](ADR-005-scd-single-file.md) 与 FAQ） |
