# 执行提示词：倒计时进度条「剩余口径」+ 绿条流光扫过 + 余额显示期快轮询（需求变更 2026-10-02）

> 面向在本工作区执行修改的 AI。改动范围：`src/DeepSeekBalanceWidget` 的 Peak 计算层、Panel 视图层、Settings、Scheduling/Balance 管线；`tests/DeepSeekBalanceWidget.IntegrationTests`。先通读本提示词再动手，改动完成后全量构建与测试须通过。文末「附：主对话编排协议」是给主对话（规划/派发方）的规程，不属于执行者的编码任务。

## 背景（现状）

- 进度条在 `Panel/PanelWindow.xaml`（倒计时文字下方）：4px 高、CornerRadius=2，两个星宽列——左列绿 Border（`Brush.Acc`）+ 右列露出灰轨道（`Brush.Line`）；列宽由 `Panel/PanelViewModel.cs` 的 `ProgressFilled` / `ProgressRemaining`（GridLength 星宽）每 tick 绑定刷新。
- 当前口径（`Peak/PeakModels.cs` 的 `ProgressCalculator`，D-09）：绿条 = **当前时段已过比例**，随时间变长；而倒计时数字 = 距下一时段切换点（`PeakEngine.NextSwitch`）的精确差值，每 1 秒 tick 刷新。**两者口径不一致**。
- 本次变更把两者统一，并给绿条加流光动画。

## 需求 A：进度口径改为「剩余 ÷ 总长」（必须）

绿条占比 `frac` 定义：

- **终点** = 下一时段切换点（现有 `NextSwitch`）。
- **起点** = 当前连续时段段的开始时刻，即上一时段切换点（上一高峰结束）；连续多日全天空闲时为该连续空闲段的起点（上一工作日 18:00）。
- **剩余** = 终点 − 当前北京墙钟（与 `CountdownText` 同源同值）。
- `frac = 剩余 ÷ (终点 − 起点)`，钳制 [0,1]。绿条 = frac，灰条 = 1 − frac。

行为要求：

1. 数字每减 1 秒，绿条同步缩一点；数字归零瞬间绿条恰好归零，翻入新时段后绿条立即回满。条与数字**严格同步**。
2. 高峰态（「距空闲时段还有」）与空闲态（「距高峰时段还有」）同规则对称，均按剩余/总长收缩。
3. `NextSwitch` 为 null（无有效数据）时：条保持满绿静止，与「--:--:--」语义一致。
4. 更新节奏不变：每 1 秒 tick 直刷，不做亚秒插值动画。
5. 实现落点建议：在 `PeakEngine` 内与 `NextSwitch` 对称地计算当前段起点（新增纯函数，便于单测）；`WidgetSnapshot` 携带新进度值；`PanelViewModel.UpdateSnapshot` 沿用现有 `ProgressFilled`/`ProgressRemaining` 两属性（语义由「已过/剩余」反转为「剩余/已过」，注意同步改注释）。XAML 两个星宽列结构可保留，绿左灰右。
6. 旧 `ProgressCalculator` 的「当前时段已过比例」口径废弃（若无处复用则删除，避免两套口径并存）。

## 需求 B：绿条流光扫过动画（必须）

形态：一道淡白高光带沿绿条**从左向右**匀速扫过并循环，像玻璃上的反光掠过。

1. **只作用于绿条填充区域**：高光必须裁剪在绿 Border 的圆角矩形内（Clip / OpacityMask），不得溢出到灰条、圆角外或文字上。绿条接近 0 宽时高光自然不可见，无需特殊处理。
2. 灰条、倒计时文字、布局尺寸（4px 高、CornerRadius=2、`Brush.Acc`/`Brush.Line`）等既有视觉语言一律不动。
3. **默认档位**：节奏 = 克制（一次扫过约 3.5 秒 + 停顿约 1.5 秒，循环约 5 秒）；强度 = 极淡（高光为白色低透明度渐变，叠加在 `Brush.Acc` 上仅隐约可见）。
4. **保留档位**（设置窗口可切换，见需求 C）：
   - 节奏：克制（默认，如上）/ 明显（约 2 秒一次、无停顿、无缝循环）
   - 强度：极淡（默认）/ 可见（一眼可辨但不刺眼）
5. 实现：WPF `Storyboard` + `TranslateTransform`（或等效合成层动画），不占用 UI 线程逐帧计算；开关关闭时必须停掉并释放动画资源，不留残影；应用关闭无泄漏。窗口隐藏/最小化时暂停动画是可选优化。
6. 开关关闭时绿条为纯色静止，其余表现（口径、灰条）不变。

## 需求 D：测试与验收（必须）

1. 更新按旧口径写的断言：`tests/DeepSeekBalanceWidget.IntegrationTests/PeakFlipIntegrationTests.cs` 现断言「翻转前进度 >99%、翻转后 <1%」，新语义下方向相反（翻转前剩余→0 即 <1%，翻转后回满 >99%），逐处检查更正；`HolidayStartupFlipIntegrationTests.cs` 等涉及进度的断言同查。
2. 新增单测覆盖新 frac 计算：工作日高峰段内、跨天晚间空闲（18:00 → 次日 09:00）、连续多日节假日空闲段、切换瞬间归零/回满、`NextSwitch=null` 满绿、[0,1] 钳制边界。
3. 新增测试覆盖需求 E 的快轮询行为：显示期 5s 触发、隐藏回设定周期、重新显示立即先刷一次、429/失败指数退避。
4. 全量 `dotnet build` + `dotnet test` 通过（按仓库惯例的 DOTNET_ROOT 私有 SDK 环境跑）。
5. **不许退化（硬验收标准）**：面板显示期间倒计时数字必须保持每秒跳动——1s 心跳（`Scheduler` 的 DispatcherTimer，伺服式绝对对齐）本身不得改动或降频；流光动画运行时同样保持。若动画或快轮询导致 tick 卡顿、漂移超一个节拍，视为验收不通过。
6. 若做 UI 冒烟：应用窗口会抢鼠标，按仓库惯例先预警再跑。

## 需求 E：余额显示期快轮询（必须）

现状：余额经 DeepSeek API 真实网络请求获取，按 `RefreshIntervalMinutes` 设置周期刷新（默认 30 分钟，设置下限 5 分钟）。

新行为：

1. **面板显示期间**：余额刷新提到每 **5 秒**一次（固定策略，不新增设置项）。走现有 Balance 管线（凭据、SecretMasker、失败语义全部沿用），触发点建议挂在 `Scheduler` 现有 1s tick 的记账逻辑里，不新建线程/定时器。
2. **面板隐藏后**：回到设定周期（默认 30min），快轮询完全停止。
3. **重新显示**：立即先刷一次，再进入 5s 节奏；显隐抖动去抖（复用 `PanelDebounce` 或等效机制），频繁显隐不得放大请求量。
4. **失败保护**：429/网络失败按指数退避（如 5s→10s→20s→…封顶 60s），成功后恢复 5s；失败时沿用现有「失败不回退」语义，不刷错误状态。
5. **设置文案**：`SettingsWindow` 中刷新间隔的说明同步改为「后台（隐藏时）刷新周期」语义，取值范围与持久化机制不变。
6. 倒计时 1s 心跳与余额刷新解耦：快轮询的任何阻塞、退避、失败都不得拖慢心跳（需求 D-5 的不许退化标准）。

## 附：主对话编排协议（给规划/派发方，非执行者编码任务）

本需求变更由主对话（ZCode 会话）规划与派发，**主对话只做规划、派发与汇报，不直接改代码**。执行与验收全部由子智能体完成，结果经主对话中转给用户。流程为三关 + 修复循环：

1. **第一关·执行子代理**：以本提示词为唯一任务书，完成全部编码改动，跑通全量 `dotnet build` + `dotnet test`（全绿才算过），回报改动清单与自查结论。
2. **第二关·验收子代理（独立）**：不看执行者的自查结论，独立复核——代码 diff 复查（对照本提示词逐条核对）、PrintWindow 实拍面板截图、visual-judge 判图（流光形态、绿左灰右、裁剪无溢出、极淡默认档）。任一不符即退回第一关修复，循环至通过。
3. **第三关·复审子代理（独立，只读）**：不改任何文件，通读最终 diff 与第二关截图，专挑遗漏与副作用（心跳退化、管线阻塞、设置兼容性、文档同步遗漏），出书面结论。
4. 三关全过 → 主对话汇总交付，由用户亲自试用后决策。

派发纪律（沿用既有约定）：失败退避重试；单命令 ≤8 分钟；执行子代理跑 UI 冒烟（会抢鼠标）前必须先向用户预警；每关结束在主对话设检查点，异常即停。
